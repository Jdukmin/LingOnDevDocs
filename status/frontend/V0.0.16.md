# Version
V0.0.16

## Summary

이 버전의 핵심 작업(`docs/workflow.md`, `docs/policies/`, `docs/ops/` 최초
작성 — [backend/V0.0.16](../backend/V0.0.16.md) 참고)에 곁들여, API Contract
Verification 과정에서 발견된 Frontend 문서 2건의 실제 오류를 정정한다.
Weather 응답 포맷 서술 오류와 Calendar MVP 범위(로컬 vs Google) 오해 소지를
바로잡는다.

## Major Changes

1. `WeatherService.md`의 응답 포맷 서술 오류 정정 — "ResponseEnvelope
   미사용, OpenWeatherMap 원본 포맷 직접 파싱"이라던 이전 서술이 Backend
   문서(`backend/docs/api/weather.md`)와 실제로 어긋났음을 발견, ICD v0.0
   envelope + 정규화된 응답을 사용한다는 Backend 문서 기준으로 정정.
2. `CalendarWidget.md`에 "MVP는 Google Calendar만 지원" 배너 추가 — 현재
   위젯이 표시하는 것은 로컬 기기 캘린더이며 Backend `GET /v1/calendar/events`
   (Google Calendar)와는 다른 데이터 소스임을 명시.

## Fixed

- `frontend/docs/services/WeatherService.md` — 응답 요약 절을 실제 Backend
  ICD 포맷(`{success, data: {location, weather, temperature, wind, clouds,
  visibility, sunrise, sunset, observed_at}, error}`)으로 교체. 단, 이
  저장소에는 실제 Flutter 소스가 없어 `weather_module.dart`가 실제로 이
  포맷을 파싱하는지는 "코드 확인 필요"로 남김(잠정적 정정).
- `frontend/docs/widgets/CalendarWidget.md` — "로컬 캘린더 = Backend
  Google Calendar API와 동일한 데이터"라고 오해될 수 있던 서술에 명시적
  경고 배너 추가, 정규 스키마는
  [requirements/domain_icd/calendar.md](../../requirements/domain_icd/calendar.md)를
  따르도록 안내.

## Architecture

- Weather Domain([requirements/domain_icd/weather.md](../../requirements/domain_icd/weather.md),
  같은 버전에서 Backend 쪽에 신규 작성됨)의 "CurrentWeather 정규 스키마"가
  Frontend 문서와 처음으로 명시적으로 대조·일치됨.
- Calendar Domain의 "MVP는 Google Calendar 단일 provider" 범위 축소
  ([backend/V0.0.16](../backend/V0.0.16.md) 참고)가 Frontend 위젯 문서에도
  동일하게 반영 — 로컬 캘린더 표시는 "병합 대상"이 아니라 "Phase 1에서
  교체될 임시 구현"으로 재정의됨.
