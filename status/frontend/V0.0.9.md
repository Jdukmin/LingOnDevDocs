# Version
V0.0.9

## Summary

Backend의 Google OAuth 완성(같은 버전, [backend/V0.0.9](../backend/V0.0.9.md))에
맞춰 Frontend 인증 흐름 문서를 갱신한 버전. ID Token 흐름과 Redirect 흐름
두 가지가 명확히 구분되어 문서화된다.

## Major Changes

1. Google Sign-In을 "ID Token(Native)"과 "Redirect(Web)" 두 흐름으로 명확히 분리.
2. `AuthController`에 `signInWithGoogleRedirect()`, `handleRedirectCallback()` 추가.
3. 응답 필드명 정정: `user.name`/`user.avatar_url` → `user.nickname`/`user.profile_image`
   (Backend V0.0.9의 DB 컬럼 확정과 일치).

## Added

- `frontend/docs/services/AuthService.md`에 "인증 흐름" 절 신설 — 흐름 1(ID
  Token)과 흐름 2(Authorization Code Redirect) 각각의 시퀀스를 명시적으로 구분.
- `AuthController.signInWithGoogleRedirect()`, `handleRedirectCallback(token, refreshToken)` 문서화.
- `GET /v1/auth/google` — Redirect 흐름 라우트를 "호출 대상(Route)" 표에 추가.

## Changed

- `frontend/docs/FeatureList.md` — "Google Sign-In (OAuth)" 단일 항목을
  "ID Token, native"와 "Redirect, Web" 2개 항목으로 분리.
- `frontend/docs/services/AuthService.md` — Request/Response 예시의
  `user.name`/`user.avatar_url`을 `user.nickname`/`user.profile_image`로 정정
  (Backend 컬럼명 확정에 따른 반영).

## Fixed

없음(이 버전은 Backend 변경사항 반영이 중심 — 자체 오류 정정은 없었음).

## Architecture

- Frontend 인증 아키텍처가 "단일 로그인 방식"에서 "플랫폼별 2가지 흐름"으로
  분화 — 이후 [requirements/domain_icd/user.md](../../requirements/domain_icd/user.md)의
  User Domain(Session 개념)의 Frontend 측 구현 선례가 된다.
