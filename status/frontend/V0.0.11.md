# Version
V0.0.11

## Summary

로그인 UI 완성을 위해 Frontend의 세션 관리 전체(자동 세션 복원, Refresh
Token 갱신, 서버측 로그아웃)를 Backend V0.0.11과 맞춰 문서화한 버전.
보안 강화(URL fragment 토큰 전달, 플랫폼 감지)도 함께 반영된다.

## Major Changes

1. `AuthRepository.refreshToken()`, `AuthController.signOut()`이 실제
   Backend 엔드포인트(`POST /v1/auth/refresh`, `POST /v1/auth/logout`)를
   호출하도록 갱신.
2. 토큰 전달 방식을 query string(`?token=`)에서 URL **fragment**(`#token=`)로
   변경 — 서버/프록시 로그 및 브라우저 히스토리 노출 방지.
3. `GET /v1/auth/me` 연동 — 로그인 후 프리로드에 city 등 프로필 필드 포함.

## Added

- `frontend/docs/services/AuthService.md` "세션 관리" 절 신설 — Refresh Token
  갱신(`POST /v1/auth/refresh`), 로그아웃(`POST /v1/auth/logout`) 각각의
  시퀀스 문서화.
- 플랫폼 감지 순서 문서화(`x_auth_platform` 쿠키 → `X-Platform` 헤더 →
  `User-Agent` → 기본값 `web`).
- `AuthRepository.refreshToken()`, `logout(refreshToken)` 메서드 문서화.

## Changed

- `frontend/docs/services/AuthService.md` — 콜백 URL 파라미터 방식을
  `WEB_CALLBACK_URL#token=...`(fragment)로 변경, `restoreSession()`이
  "필요 시 refresh"까지 수행하도록 갱신, `signOut()`이 서버측 revoke
  (`POST /v1/auth/logout`)를 호출하도록 갱신.
- `frontend/docs/FeatureList.md` — "Refresh Token 재발급"을 "재발급 로직
  없음"에서 "UI 연동 필요(백엔드는 구현 완료)"로 갱신, 예정 기능 절의
  "Refresh Token 갱신 로직"을 "Refresh Token 자동 갱신(인터셉터) — High,
  백엔드 완료·프론트 401 인터셉터 필요"로 구체화.

## Architecture

- Session 개념(로그인 상태 + rotation)이 Frontend에서도 완결됨 — Backend
  V0.0.11과 함께 User Domain의 Session 개념 전체가 양쪽에서 대응된다.
- **참고**: 이 시점 문서(`AuthService.md`)의 "Refresh Token 재발급 UI 연동"
  항목은 실제로는 이 버전 이후에도 오랫동안 미해결로 남는다 — 2026-07-23
  기준 `frontend/docs/FeatureList.md` 스텁 절에 여전히 "Refresh Token 재발급
  UI 연동" 항목으로 존재([status/current_status.md](../current_status.md) §3
  "다음 작업" 3번 참고).
