# Version
V0.0.13

## Summary

Google Calendar 연동을 Backend에 최초로 추가한 버전("minor update for
calendar ICD"). 로그인 OAuth와 완전히 독립된 두 번째 OAuth2 namespace(Calendar
동의, `calendar.readonly` scope)와 `GET /v1/calendar/events` 엔드포인트가
이 버전에서 구현된다.

## Major Changes

1. Calendar 동의 플로우(Flow 3) 최초 구현 — `GET /v1/auth/google/calendar`
   + callback, 로그인과 별개의 `@fastify/oauth2` namespace.
2. `GoogleCalendarAPI` + `GoogleTokenService` 최초 구현 — Calendar 토큰
   자동 갱신 포함.
3. `migrations/003_google_calendar_tokens.sql` — `users` 테이블에 Calendar
   토큰 3개 컬럼(`google_access_token`, `google_refresh_token`,
   `google_token_expire`) 추가.
4. `GET /v1/calendar/events` 최초 구현.

## Added

- `src/db/googleTokenRepository.ts`.
- `src/gateway/{GoogleCalendarAPI,GoogleTokenService}.ts`.
- `src/route/LingOnCalendar.ts`.
- `migrations/003_google_calendar_tokens.sql`.

## Changed

- `src/plugins/LingOnOAuth/GoogleOAuth.ts` — 두 번째 독립 namespace
  (`app.googleCalendarOAuth2`) 추가.
- `src/route/LingOnAuth.ts` — Flow 3(Calendar 동의) 절 추가.
- `src/route/LingOnUsers.ts` — 소규모 조정.

## Fixed

없음.

## Architecture Impact

- **Tool Domain의 최초 실질적 구현체** — `GoogleCalendarAPI`가 이후
  DevDocs [requirements/domain_icd/tool.md](../../requirements/domain_icd/tool.md)가
  정의하는 "외부 시스템에 대한 어댑터" 계약의 실제 선례가 된다.
- Calendar 동의 흐름이 로그인 OAuth와 완전히 분리된 별도 client 등록으로
  설계됨 — 이 원칙은 이후 `docs/policies/security_policy.md`의 근거가
  된다.
- 이 시점의 응답 필드는 `title`/`startTime`/`endTime`(camelCase 커스텀
  네이밍)으로 구현됨 — 이는 `backend/docs/api/calendar.md`(Google 원본
  필드명 보존을 문서화)와 어긋나는 상태로 V0.0.17까지 유지된다
  (V0.0.17에서 P0로 수정).
