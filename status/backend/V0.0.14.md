# Version
V0.0.14

## Summary

**전략적 전환점.** "LetMeKnow는 Dashboard가 아니라 Personal Action OS다"라는
제품 철학 전환에 따라, `docs/strategy/`, `docs/roadmap/`, `docs/decisions/`,
`docs/icd/`(Action Layer API 제안), `requirements/`(RDD 절차 + System/Layer
Requirement 8종), `requirements/domain_icd/`(11개 Domain 계약)이 이 버전에서
**전부 최초로 작성**됐다. `backend/docs/` 자체의 실질적 구현 변경은 거의
없다 — 이미 구현되어 있던 API들 위에 "Action Layer 관점에서 이들을 어떻게
재해석할지"를 알리는 배너와, 오래된 상태 문구 정정만 있었다.

## Major Changes

1. **Domain ICD 최초 도입**([requirements/domain_icd/](../../requirements/domain_icd/)) —
   API/State/DB보다 상위에서 비즈니스 도메인 계약을 정의하는 새 계층.
   Intent/Action/Tool/Workflow/Calendar/Reminder/Notification/Dashboard/HomeAssistant/NAS/User
   11개 Domain 최초 작성.
2. **Action Layer API 제안**([docs/icd/action_layer_api.md](../../docs/icd/action_layer_api.md)) —
   `POST /v1/actions/execute` 등 신규 API 제안. 기존 API는 삭제·변경하지 않음(Keep/Wrap 분류).
3. **Requirements(RDD) 체계 최초 도입** — System Requirement(SYS-001~010) +
   8개 Layer Requirement 문서, Status/Progress 규칙 확정.
4. **오래된 "인증 미구현" 상태 문구 정정** — `api/apikey.md`, `api/settings.md`가
   V0.0.7 시절 문구("authentication is not implemented yet")를 여전히 갖고
   있었던 것을 V0.0.9(실제 인증 구현)와 일치하도록 정정.
5. 두 번째 커밋("unregulated parameter fixed")에서 `action.md` ↔
   `action_layer_api.md` 간 State 이름 불일치(`Cancelled`/`timed_out` 누락 등)를
   발견·정정 — snake_case를 단일 기준으로 확정.

## Architecture

- **Domain ICD가 API ICD보다 상위 계층으로 확정** — Backend/Frontend는
  API가 아니라 Domain ICD를 기준으로 구현하도록 원칙이 바뀜(단, 기존 API는
  변경하지 않고 유지).
- 기존 `backend/docs/api/*`는 전부 "Keep" 또는 "Wrap" — Action Layer가
  기존 API를 대체하지 않고 그 위에 새 진입점을 추가하는 구조로 확정.
- State 이름 표기 컨벤션(소문자 snake_case)이 이 버전에서 최초로 명문화됨 —
  이후 모든 Domain ICD 문서가 따라야 할 기준.
