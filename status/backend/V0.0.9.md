# Version
V0.0.9

## Summary

Google OAuth 로그인이 실질적으로 동작하기 시작한 버전. ID Token 흐름과
Redirect 흐름 두 가지가 `LingOnAuth.ts`에 구현되고, `GoogleAuthAPI`
게이트웨이와 `GoogleOAuth` 플러그인이 추가된다. `users` 테이블의
`provider_sub`가 `provider_id`로 리네임되는 첫 마이그레이션도 이 버전에서
등장한다.

## Major Changes

1. `GoogleAuthAPI` 게이트웨이 최초 구현(`google-auth-library` 기반 ID
   Token 검증).
2. `GoogleOAuth` 플러그인 최초 구현(`@fastify/oauth2` 조건부 등록, Redirect 흐름).
3. `migrations/001_rename_provider_sub_to_provider_id.sql` — 최초 마이그레이션 파일.
4. `LingOnAuth.ts`가 ID Token(`POST /v1/auth/google`) + Redirect(`GET
   /v1/auth/google`, `/callback`) 두 흐름을 모두 구현.

## Added

- `src/gateway/GoogleAuthAPI.ts`.
- `src/plugins/LingOnOAuth/GoogleOAuth.ts`.
- `migrations/001_rename_provider_sub_to_provider_id.sql`.

## Changed

- `src/route/LingOnAuth.ts` — 골격(V0.0.8)에서 실제 두 흐름 구현으로 확장(+175/-est).
- `src/db/userRepository.ts` — `provider_id` 컬럼 반영, `upsertByProvider` 추가.
- `src/core/utils/Jwt.ts` — 발급/검증 로직 확장.
- `src/route/LingOnUsers.ts` — 인증 연동 반영.

## Fixed

없음(신규 기능 구현이 중심).

## Architecture Impact

- User Domain의 Session 개념이 이 버전에서 최초로 실제 동작 — `req.ctx.userId`가
  이제 인증된 요청에서 실제로 채워짐(V0.0.7~8 시점의 "데이터 계층만 존재"
  상태 해소).
- Redirect 흐름은 이 시점에 `GOOGLE_CLIENT_SECRET`/`GOOGLE_CALLBACK_URL`
  등 필수 env var가 없으면 `501 NOT_IMPLEMENTED`를 반환하도록 설계 — 이후
  모든 버전에서 이 패턴(옵셔널 기능의 명시적 501)이 유지됨.
