# Version
V0.0.16

## Summary

"서비스 MVP 프로세스" 정리 버전("service MVP process minor update"). 이
버전의 핵심은 두 가지다: (1) V0.0.14에서 시작된 SSOT 정리(Docs Revision)를
완결하며 `backend/docs`에 남아있던 마지막 두 개의 오래된 문구를 정정하고,
(2) `docs/policies/`, `docs/ops/`, `docs/workflow.md`(개발 SOP)를 최초로
작성해 출시 전 정책/운영 절차의 뼈대를 세운다. Domain ICD에는 Weather/Todo/Settings
3개 Domain이 신규 추가된다.

## Major Changes

1. **`docs/workflow.md` 최초 작성** — Step 0~6(Domain Freeze → Backend
   개발/검증 → Frontend 개발/검증 → 통합 검증 → 문서 갱신) SOP, Phase 0~10
   개발 순서, 출시 전 필수 체크리스트, AI 조직 운영 구조.
2. **`docs/policies/`, `docs/ops/` 최초 작성** — Error/Logging/Security/Privacy
   정책, Deployment/Data SOP, Monitoring 절차(대부분 "기존 구현을 정책화" +
   "미수립 항목을 정직하게 Not Started로 기록").
3. **`backend/docs`의 마지막 두 개 오래된 문구 정정**(V0.0.14 SSOT 정리의
   연장) — `DevelopmentGuide.md`의 auth 관련 오래된 시퀀스 다이어그램/"미구현"
   목록, `services/google-auth.md`의 `avatar_url` 오기.
4. Domain ICD에 Weather/Todo/Settings 3개 Domain 추가(11개 → 14개) —
   Weather는 "이미 완전히 구현됐는데 Domain ICD가 없다"는 지적에 대한 대응,
   Settings는 User Domain의 `Preference`를 분리.

## Added

- `docs/workflow.md` — 개발 SOP 전체(340줄, 이 저장소의 개발 프로세스 canonical 문서).
- `docs/policies/{error_policy,logging_policy,security_policy,privacy_policy}.md` — 4개 정책 문서 최초 작성.
- `docs/ops/{deployment_sop,data_sop,monitoring}.md` — 3개 운영 SOP 최초 작성.
- `requirements/domain_icd/{weather,todo,settings}.md` — 신규 Domain 3종.

## Changed

- `docs/icd/README.md`, `docs/icd/action_layer_api.md`, `docs/icd/prompt_playbook.md` —
  상위 SOP(`docs/workflow.md`)를 가리키는 배너 추가, ActionExecution State
  섹션에 "정정 2026-07-21" 각주 보강.
- `requirements/domain_icd/{README,tool,user,workflow}.md` — Weather/Todo/Settings
  추가에 따른 목록/참조 갱신, State 표기 추가 정정.
- `requirements/domain_icd/calendar.md` — **MVP 범위 축소**: "로컬 캘린더 + Google
  Calendar 병합" 방침을 폐기하고 "MVP는 Google Calendar만 지원, 로컬 캘린더는
  병합이 아니라 교체 대상"으로 변경. `CalendarEvent` 정규 스키마(snake_case)
  최초 정의.
- `requirements/domain_icd/domain_analysis.md` — Weather/Todo/Settings를
  "제안"에서 "작성 완료"로 갱신.

## Fixed

- `backend/docs/DevelopmentGuide.md` — (1) Request lifecycle 시퀀스 다이어그램의
  `Policy->>Handler: (no-op until auth is implemented)`를 실제 구현("verifies
  Bearer JWT, sets req.ctx.userId")으로 정정. (2) "What's not yet implemented"
  절에서 `POST /v1/auth/refresh`, `POST /v1/auth/signout`을 "미구현"으로
  잘못 나열하던 것을 정정(V0.0.11에서 이미 구현 완료됐고, 이름도 `signout`이
  아니라 `logout`) — `req.ctx.apiKeyId`만 여전히 유효한 미구현 항목으로 남김.
- `backend/docs/services/google-auth.md` — Google `picture` 필드가 `avatar_url`로
  rename된다는 오기를 정정(실제로는 `profile_image` — V0.0.9에서 이미
  `nickname`/`profile_image`로 확정됐던 컬럼명과 이 문서만 불일치했음).

## Architecture

- **개발 SOP가 이 버전에서 처음으로 공식화됨** — 이후 모든 신규 기능은
  `docs/workflow.md` Step 0~6을 따라야 한다.
- Calendar Domain의 MVP 범위가 "다중 소스 병합"에서 "Google Calendar
  단일 provider"로 좁혀짐 — 이후 [status/roadmap.md](../roadmap.md) Phase 1의
  완료 조건과 일치.
- Error Policy가 409/422/503을 "신규 정책 — 현재 미사용"으로 명시 —
  향후 Action Layer(Phase 1/4) 구현 시 최초 적용 대상으로 지정됨.
