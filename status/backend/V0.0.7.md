# Version
V0.0.7

## Summary

커밋 메시지("Added OAuth(not completed)")와 달리, 이 커밋의 실제 diff에는
OAuth 코드가 없다 — 실제로 추가된 것은 User/Settings/API Key의 DB
Repository와 Route, 그리고 AES-256-GCM 암호화 유틸(`encrypt.ts`)이다.
커밋 메시지는 "다음에 할 일(OAuth)"에 대한 의도 표시로 보이며, 실제 인증
코드는 다음 버전(V0.0.8~0.0.11)에서 순차적으로 추가된다.

## Major Changes

1. `user_api_keys`, `ai_settings`, `ui_settings`, `users` 4개 테이블에 대한
   Repository 계층 최초 구현.
2. AES-256-GCM 암호화(`encrypt.ts`) — BYOK API 키 암호화 저장의 기반.
3. `/v1/apikey/*`, `/v1/settings/*`, `/v1/users/*` 라우트 최초 구현
   (단, 이 시점에는 인증 미들웨어가 없어 `req.ctx.userId`가 항상 비어있는
   상태로 존재).

## Added

- `src/db/{apiKeyRepository,encrypt,settingsRepository,userRepository}.ts`.
- `src/route/{LingOnApiKey,LingOnSettings,LingOnUsers}.ts`.
- `CLAUDE.md` 최초 작성(이후 여러 버전에 걸쳐 지속 갱신됨).

## Architecture Impact

- User Domain의 데이터 계층(프로필, 설정, BYOK 키)이 인증보다 먼저
  구축됨 — 인증(Session) 없이 데이터 계층만 존재하는 과도기 상태.
- `user_api_keys`/`ai_settings`/`ui_settings`는 이 시점에 마이그레이션
  파일 없이(코드에서 역추론되는 형태로) 도입됨 — 이후 Backend Schema
  Verification Report(V0.1.0)가 이를 "5개 테이블 중 마이그레이션 커버리지
  없음"으로 재확인한다.
