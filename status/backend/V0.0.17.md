# Version
V0.0.17

## Summary

"functional update for first launch" — 이 저장소 최초의 정식
**Verification Report 기반 수정 커밋**이다. `BACKEND_VERIFICATION_REPORT.md`
(2026-07-24, 이 커밋에 포함됨)가 DevDocs SSOT 대비 실제 코드를 감사한 뒤
발견한 드리프트를 이 한 커밋에서 전부 수정한다 — Calendar 응답 필드명
SSOT 불일치(P0), `user_api_keys` 라이브 DB 스키마 drift(런타임 500 오류),
`.env.example` 오기, 오래된 코드 주석을 바로잡는다.

## Major Changes

1. **[P0]** `GET /v1/calendar/events` 응답 필드명을 SSOT
   (`backend/docs/api/calendar.md`)에 맞춰 정정 — `title`/`startTime`/`endTime`
   → `summary`/`start`/`end`(Google 원본 필드명 보존).
2. **[P0]** 문서화되지 않은 `from`/`to`/`limit` 쿼리 파라미터 제거(V0.0.15에서
   추가됐던 것).
3. **[Critical]** `migrations/005_fix_user_api_keys_schema.sql` — 라이브
   DB의 `user_api_keys` 스키마 drift 수정(`iv` 컬럼 제거,
   `encrypted_key`를 `bytea`→`text`로 변경). 이 drift로 인해 모든 `PUT
   /v1/apikey/:provider` 호출이 500으로 실패하고 있었음 — 실제 라이브
   DB에 접속해서만 발견 가능했던 버그.
4. `migrations/004_fix_settings_schema.sql` — `ai_settings`/`ui_settings`
   스키마 정합성 수정(같은 클래스의 이전 drift 수정, 이 커밋 이전
   작업분이 포함됨).
5. `Logger.ts` — `Authorization` 헤더/OAuth `code`/`access_token` 쿼리
   파라미터가 Pino 로그에 남지 않도록 redact 강화.

- `src/route/LingOnCalendar.ts` — 쿼리 파라미터 제거(위 2번), 코드 간소화(-60줄).
- `src/core/utils/Logger.ts` — redaction 로직 확장(+67줄).
- `src/db/settingsRepository.ts`, `src/route/LingOnSettings.ts` — 스키마 정합성 반영.

  주석 정정(실제로는 V0.0.11부터 구현 완료 상태였음).

## Fixed

- Calendar 응답 필드명 SSOT 불일치(P0).
- `user_api_keys` 라이브 DB 스키마 drift(500 오류의 근본 원인).
- `src/config/FastifyDefinition.ts`의 오래된 "req.ctx.userId는 인증
  구현 전까지 undefined" 주석(사실과 다른 상태로 여러 버전에 걸쳐 방치됐던 것).
- `.env.example`의 잘못된 변수명(`FRONTEND_CALLBACK_URL` → `WEB_CALLBACK_URL`,
  `ANDROID_CALLBACK_URL` 누락 보완).

## Architecture Impact

- 이 버전 이후 Backend의 Calendar API 계약이 SSOT와 완전히 일치하는
  상태로 안정화됨 — Frontend가 이 계약에 맞춰 대응 수정을 하도록 트리거함
  (`FRONTEND_VERIFICATION_REPORT.md`, 같은 날 Frontend 저장소에서 대응).
- DB 스키마가 "문서·코드는 일치하지만 라이브 DB만 독립적으로 drift"할 수
  있다는 것이 실증됨 — 이후 Backend Schema Verification Report가 이
  클래스의 문제를 정식 리스크(마이그레이션 커버리지 부족)로 격상시킨다.
