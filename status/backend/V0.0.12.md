# Version
V0.0.12

## Summary

Google Calendar 연동을 Backend에 최초로 추가한 버전이다("minor update for
calendar api"). 로그인용 OAuth와 완전히 분리된 별도의 Calendar 동의(consent)
플로우와, 실제 일정 조회 API가 이 버전에서 완성된다.

## Major Changes

1. Google Calendar 동의 플로우(Flow 3) 도입 — `GET /v1/auth/google/calendar` +
   callback, 로그인과 별개의 OAuth2 namespace/scope(`calendar.readonly`).
2. `GET /v1/calendar/events` 최초 구현 — 사용자의 primary calendar에서 오늘 이후 일정 조회.
3. `GoogleTokenService` 도입 — Calendar 토큰 자동 갱신(만료 60초 전 refresh).
4. `users` 테이블에 Calendar 토큰 컬럼 3종 추가(`google_access_token`,
   `google_refresh_token`, `google_token_expire`, 모두 AES-256-GCM 암호화).

## Added

- `backend/docs/api/calendar.md` — `GET /v1/calendar/events` 최초 문서화
  (Request/Response, Error 코드 `CALENDAR_NOT_CONNECTED`/`CALENDAR_TOKEN_REFRESH_FAILED`,
  Security invariants).
- `backend/docs/services/google-calendar.md` — `GoogleCalendarAPI` + `GoogleTokenService` 최초 문서화.

## Changed

- `backend/docs/api/auth.md` — Flow 3(Calendar 동의) 절 추가, `x_calendar_user_id`
  쿠키 기반 콜백 사용자 식별 설명 추가.
- `backend/docs/database/users.md` — Calendar 토큰 3개 컬럼 추가(로그인 컬럼과
  완전히 독립적임을 명시).
- `backend/docs/plugins/google-oauth.md` — 두 번째 독립 OAuth2 namespace
  (`app.googleCalendarOAuth2`, `calendar.readonly` scope) 추가, 활성화 조건
  (`GOOGLE_CALENDAR_CALLBACK_URL`) 명시.
- `backend/docs/routes/README.md`, `backend/docs/services/README.md`,
  `backend/docs/FeatureList.md` — 신규 라우트/서비스 반영.

## Fixed

없음.

## Architecture

- **Tool Domain의 최초 실질적 구현체**가 이 버전에서 등장 — `GoogleCalendarAPI`가
  이후 [requirements/domain_icd/tool.md](../../requirements/domain_icd/tool.md)(V0.0.14)가
  정의하는 "외부 시스템에 대한 어댑터" 계약의 실제 선례가 된다.
- Calendar 동의 흐름이 로그인 OAuth와 **완전히 분리된 별도 client 등록**으로
  설계됨 — 이 원칙은 이후 [docs/policies/security_policy.md](../../docs/policies/security_policy.md)(V0.0.16)의
  "OAuth" 절 정책 근거가 된다.
